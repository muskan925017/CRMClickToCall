# LeadZam CRM Click-to-Call

A simple CRM click-to-call application that allows a user to send a call request from a web dashboard to an Android device using Firebase Cloud Messaging (FCM). When the user taps the notification's **Call** action, the Android app opens the native phone dialer with the lead's phone number prefilled.

## Features

- CRM dashboard displaying sample leads, phone numbers, and lead stages.
- Call request submission from the web dashboard.
- Node.js and Express backend API.
- Firebase Cloud Messaging integration for Android notifications.
- Android app developed with Kotlin.
- Native dialer opens when the user taps the notification's Call action.
- Request status feedback and basic error handling.
- Firebase credentials kept on the server.

## Technology Stack

- **Web:** React, Vite, JavaScript, CSS
- **Backend:** Node.js, Express.js
- **Android:** Kotlin, Android SDK
- **Push notifications:** Firebase Cloud Messaging (FCM)
- **Firebase server integration:** Firebase Admin SDK

## Prerequisites

Install the following tools:

- Node.js and npm
- Android Studio and Android SDK
- Java/JDK version compatible with the Android project's Gradle configuration
- A physical Android device for notification testing
- A Firebase project with Firebase Cloud Messaging enabled

## Setup Instructions

### 1. Configure Firebase

1. Open the Firebase Console and select your Firebase project.
2. Register the Android application using the package name configured in the Android project.
3. Download `google-services.json`.
4. Place `google-services.json` in the Android app module's directory, normally `android-app/app/`.
5. Enable Firebase Cloud Messaging for the project.
6. Generate a Firebase service-account key for server-side Firebase Admin SDK access.

**Security:** Never commit the Firebase service-account JSON file, private credentials, or device registration tokens to a public repository.

### 2. Configure the backend

Open a terminal and navigate to the backend directory:

```bash
cd server
npm install
```

Create a `.env` file inside `server/`:

```env
PORT=5000
FCM_DEVICE_TOKEN=YOUR_ANDROID_FCM_TOKEN
```

Replace the placeholder with the FCM registration token generated by the Android application.

Place the Firebase service-account JSON file at:

```text
server/firebase-service-account.json
```

The backend must use this file to authenticate with Firebase Admin SDK. Keep it private and excluded from Git.

Start the backend:

```bash
npm run dev
```

The backend should run at `http://localhost:5000`.

Check its health endpoint:

```text
http://localhost:5000/api/health
```

### 3. Configure and run the web dashboard

Open another terminal:

```bash
cd crm-web
npm install
npm run dev
```

Open the local URL printed by Vite in the terminal.

The web dashboard sends requests to:

```text
http://localhost:5000/api/calls
```

Make sure the backend is running before testing a call request.

### 4. Build and run the Android application

Open the `android-app` project in Android Studio and allow Gradle synchronization to finish.

Connect an Android phone with USB debugging enabled.

From a terminal inside the `android-app` directory, run:

```powershell
.\gradlew.bat installDebug
```

Open the installed app and allow notification permission when prompted.

Retrieve the FCM registration token using the app's token screen and copy it into the backend's `server/.env` file as `FCM_DEVICE_TOKEN`.

Restart the backend after changing `.env`.

**Important:** `localhost` in the web browser refers to the computer running the browser. If the dashboard is accessed from another device, update the API URL and configure network access appropriately.

## How It Works

1. The user selects a lead and clicks **Call** on the web dashboard.
2. The React application sends the lead ID, name, and phone number to the Express API.
3. The backend validates the request and sends an FCM data message to the registered Android device.
4. The Android Firebase messaging service receives the message and displays a notification.
5. The user taps the notification's **Call** action.
6. Android opens the native dialer with the lead's phone number prefilled.
7. The user decides whether to place the call.

The application does not automatically place phone calls.

## API

### Health check

`GET /api/health`

Confirms that the backend is running.

### Send a call request

`POST /api/calls`

Example request body:

```json
{
  "leadId": "test-lead-001",
  "name": "Test Lead",
  "phone": "+919876543210"
}
```

A successful request returns a response indicating that the backend accepted the request for sending to the Android device. An invalid request, missing FCM token, or Firebase send failure should return an error response.

- Confirm that the Android phone receives a notification.
- Tap the notification's Call action and verify that the native dialer opens with the correct number.
- Test notifications with the Android app open and in the background.
- Stop the backend and confirm that the web dashboard displays a request error.
- Restart the backend and verify that call requests work again.
- Test invalid phone numbers and missing FCM configuration.

## Security

The following files must not be committed to Git:

- `.env`
- `firebase-service-account.json`
- `node_modules/`

Never publish Firebase service-account credentials or private tokens. If a service-account key is accidentally exposed, revoke it and generate a new one.

## Current Limitations

- The dashboard uses sample lead data.
- Call requests are not stored in a persistent database.
- The backend's accepted status indicates that Firebase accepted the message for sending; it does not guarantee that the device received it.
- The FCM token must be kept up to date if the Android device registration token changes.
- The app opens the dialer but does not place calls automatically.
